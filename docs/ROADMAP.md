## 3. 下一阶段：真实业务试验

目标：证明实际来源下报告有用，而不只证明框架能运行。

1. 配置一个工具调用模型、2–4 个官方 HTML 来源；先不接额外付费服务。
2. 完成一次 live 基线与后续变化运行，人工打开每条引用；检查发布时间、适用条件与数值。
3. 标注至少 10–20 个可复核案例，区分事实、推断、噪声、缺失和抓取失败。
4. 配置嵌入和 HTTP 模型 Reranker，在相同查询集比较召回、排序和延迟。保留 lexical 对照。
5. 需要云端实验时显式运行 `signaldesk-eval --langsmith`；按数据授权开启真实任务 trace。
6. 记录成功率、人工支持率、耗时、token/调用量与实际费用；没有价格或计量数据不编造成本。

退出条件：真实运行与人工标注可复核，效果和成本达到使用者目标；固定夹具全部通过。

## 4. 生产与持续使用

顺序按依赖推进，每项单独验收：

1. 数据迁移与备份恢复：引入 Alembic、升级路径、备份还原演练。
2. 用户与项目权限：身份、租户隔离、密钥存储、审计与请求限流。
3. 任务执行：持久化队列、worker 租约/心跳、幂等、关闭与跨进程恢复；通过后再启多 worker。
4. 调度与通知：时区/执行窗口、错过执行、暂停、去重、只通知有意义变化、投递幂等。
5. 采集与记忆质量：RSS/官方 API、页面去噪、中文分词、记忆冲突/容量、历史版本检索。

当前共享 Bearer token 与项目过滤不等于多租户权限；本地协程不等于分布式队列。
