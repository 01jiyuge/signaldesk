# V0.4.4 · 状态、索引与协议收尾

日期：**2026-10-23**。版本：**0.4.4**。延续 [V0.4.3 的采集、检索与交互边界](./V0.4.3_UPGRADE.md)，本轮修复异常鉴权、事件游标、项目锁、向量回填、报告安全和恢复后的状态竞态，并完善 A2A 调用收尾。最终验收结果见第 7 节。

## 1. 统一 Bearer 校验与事件游标

业务 API、项目记忆、Sandbox、AG-UI、A2A 的 Agent Card、JSON-RPC 与委托入口，共用 `auth.py` 的 Bearer 校验。凭据使用 ASCII 字节进行常量时间比较；原始请求头包含非 ASCII 字节时返回 `401`，不再让字符串比较异常变成 `500`。缺少、错误或不支持的认证凭据继续返回 `401` 和 `WWW-Authenticate: Bearer`。

`API_TOKEN` 应设置为随机 ASCII Token。未配置 Token 时的本地访问方式保持不变；公开健康检查也不改为需要鉴权。共享 Token 仍不是项目级授权或多租户身份系统。

事件游标与当前 `events.id` 的数据库整数类型保持一致：

| 输入 | 有效范围 | 非法输入 |
| --- | --- | --- |
| `GET /api/runs/{id}/events?after=N` | `0`–`2147483647` | `422` |
| `GET /api/runs/{id}/ag-ui?after=N` | `0`–`2147483647` | 流开始前返回 `422` |
| AG-UI `Last-Event-ID` | 相同数据库事件游标范围 | 流开始前返回 `422` |

负数、非整数和过大值不会再进入数据库整数绑定，避免 SQLite 或 PostgreSQL 的绑定溢出导致 `500`。AG-UI 同时收到有效查询游标与请求头游标时，仍从两者较大的位置续传。本轮不修改事件表类型，也不改变事件 ID 的生成方式。

## 2. 项目锁按参与者回收

项目配置编辑与运行状态写入继续共享每项目事务锁。锁记录同时计入持有者和等待者，在最后一个参与者退出后删除；正常返回、缺失项目、冲突、异常或等待取消都会完成计数收尾。

此前对大量不存在的项目 ID 请求编辑，虽然返回 `404`，仍可能永久留下对应锁记录。现在失败请求不会累积空锁。取消一个等待者也不会移除其他持有者或等待者仍在使用的锁；持有者取消后完成事务退出，后续写入可以继续。

数据库事务和活动运行唯一索引继续保护“每项目仅一个 queued/running”的约束。这个锁回收改动没有增加跨进程队列、worker 所有权或分布式恢复能力。

## 3. live 来源补齐缺失向量与重试复用

项目可能先在 `ENABLE_VECTOR_SEARCH=false` 时完成基线，随后才启用 PostgreSQL/pgvector。此前后续页面正文未变时会跳过嵌入，导致这些来源一直缺少向量。

现在 live 保存阶段对全部当前快照统一检查缺失向量，首次、变化与未变化来源走同一条回填路径。不存在可复用结果时才调用嵌入；运行完成后，相同内容的后续运行复用向量，检索仍返回最新成功快照。

复用其他运行的向量，要求同项目、同 URL、同正文 hash，且所属运行已经 `completed`。本次运行中相同快照 ID 已提交的索引写入，即使报告尚未完成保存，也可直接复用。因此，基线或变化来源在“嵌入已落库、报告保存失败”后恢复，不会因为重新进入保存节点而再次嵌入；其他失败运行的向量不会因此成为可复用历史。

满足既有“来源与研究上下文均未变化”条件时，仍跳过研究模型。缺失向量回填可以单独调用嵌入服务，因此“未调用研究模型”不代表这次运行没有外部调用或嵌入费用。demo 不调用嵌入服务；未启用向量检索时不进入回填。

回填范围是本次 live 运行的来源快照，不是对全部历史的离线批处理。它也不提供嵌入模型或维度迁移；修改 `EMBEDDING_MODEL` 或 `EMBEDDING_DIMENSIONS` 后，仍需按索引迁移方案重建，不能将旧向量当作新模型结果复用。

## 4. 报告完成前校验与旧报告导出

报告及证据在完成保存前检查能否序列化为标准 JSON 并编码为有效 UTF-8。未配对的 Unicode surrogate、非有限数值等无效内容不能成为已完成业务报告。证据 ID 必须唯一，重复 ID 在引用核验阶段被拒绝，不能通过字典覆盖其中一项来形成歧义引用。

这些检查延续现有引用规则：每条引用必须指向证据清单中的 ID，quote 必须存在于对应原文。它们保证结构与引用机械一致性，不证明资料真实、引文支持全部推断或建议合理。

Markdown 与 JSON 导出还检查完整的原始运行载荷，包含旧库和额外字段。包含无效文本、非有限数值或不一致证据的旧报告，沿用导出不可用的 `409` 响应，避免在 UTF-8 编码时触发 `500`，也不静默替换或丢弃原内容后导出。

本轮不会自动修复或删除历史报告。需要保留的旧数据应先备份，再针对报告来源和内容处理。

## 5. 恢复后的状态与搜索保护

对同一运行执行恢复或取消时，控制台使旧观察请求失效。迟到的详情 GET、JSON 兼容轮询和旧 SSE 事件不能把恢复后的新状态覆盖回旧状态；合法的 `failed → running` 恢复仍可展示。

选中运行和历史列表共用更新时间比较，保留 `updated_at` 的微秒精度，避免同一毫秒内的状态更新被当成相同时间或按到达顺序倒退。这是客户端响应合并规则，服务端仍按已有状态与检查点契约执行。

SQLite 原始 SQL 返回的无时区日期字符串统一补充 UTC 时区，检索结果与任务原文证据显示同一采集时刻，避免浏览器把 UTC 字符串当成本地时间。

编辑搜索关键词时立即中止或失效旧请求，清除上一个词的结果并显示待搜索状态；显式搜索才发起新请求，清空关键词后恢复当前证据。较早查询的迟到结果、研究详情刷新和兼容轮询不能覆盖当前有效搜索。

## 6. A2A 整体调用预算与已确认结果

A2A 客户端增加覆盖 Agent Card 解析、SDK RPC 及完整响应流读取的整体异步网络时间预算，沿用 `A2A_TIMEOUT_SECONDS`。单个 HTTP 操作超时不能限制持续收到少量数据的长响应，因此需要这层整体预算。

SDK 关闭与 HTTPX `aclose()` 另由独立任务持有，每次关闭最多使用 5 秒清理宽限；父调用超时或重复取消不会半途打断收尾。宽限届满后取消并等待可协作的关闭任务；异常、超时和外部取消也会退出 HTTPX 上下文。关闭与数据库确认写入可能追加收尾等待，因此 `A2A_TIMEOUT_SECONDS` 不是严格的端到端硬截止。

尚未取得远端任务确认时超时，公开错误为可重试的 `a2a_timeout`，经业务 API 返回 `503`；原有 `PENDING` 登记保留，不自动补发创建 POST。调用方应核对原请求并显式重试，远端恰好一次执行仍依赖远端幂等支持。

远端结果先完成本地登记，再发布已确认状态；登记收尾持有独立任务并处理调用方取消。已确认的发送或查询结果，不因随后在登记或连接关闭窗口到达时间预算而丢失，调用方可使用已保存结果。

取消成功必须得到远端 canonical `CANCELED` 结果，预查询中的 `WORKING` 不能冒充取消成功；已完成等终态取消冲突继续返回 `409`。

## 7. 升级与验收

本轮无需清空任务、报告、快照、检查点或 Store。升级前仍先备份持久化数据，更新依赖并重启。未变化来源回填沿用现有向量配置，没有增加模型或维度迁移开关；事件游标也没有扩大数据库 ID 类型。

完整 Python 回归 **427 项通过**，其中真实 PostgreSQL **9 项**、真实 Docker **3 项**（一项 PostgreSQL 测试同时使用 Docker）。前端行为测试 **19/19 通过**；Ruff 检查、格式、JS 语法与锁文件检查通过；离线评测 **9/9 场景、55/55 项期望匹配**。验收范围包括：

- 所有鉴权入口的异常凭据 `401`、空 Token 本地兼容、JSON/SSE 游标和请求头上界。
- 缺失项目请求不累积锁，等待者与持有者取消后锁及数据库仍可使用，并发项目编辑与创建任务约束保持。
- 先关闭、后启用向量检索时，未变化来源首次补齐与后续复用；基线或变化来源在嵌入落库、报告失败后的同快照重试复用，保持研究模型跳过与项目隔离。
- 报告无效 Unicode、非有限值、重复证据 ID 的完成前拒绝，以及旧报告导出 `409`。
- 同运行恢复后的 GET、JSON、SSE 乱序响应，微秒更新时间和搜索输入变更。
- A2A 慢流和关闭预算、已确认 ACK 保留、未确认 `PENDING`、重复取消与远端取消结果。

浏览器在独立、合成数据的 HTTP 服务上实际验证：完成演示任务，发起一个延迟 3 秒的 Northstar 搜索后将关键词改为 Orbit；旧响应不能覆盖待搜索状态，显式搜索后只展示 Orbit 证据。也验证了任务原文与检索结果的时间一致。恢复、微秒排序及省略报告后的详情补取由完整生产脚本的受控 HTTP/SSE 测试验证。

历史测试结论保留在 [V0.4.3 说明](./V0.4.3_UPGRADE.md)，不作为本轮已经完成验收的依据。运行命令和真实依赖的显式测试开关见 [OPERATIONS.md](./OPERATIONS.md)，每次发布的云端结果见 [GitHub Actions](https://github.com/01jiyuge/signaldesk/actions/workflows/ci.yml)。

当前仍面向本地单用户、单进程。受控 HTTP、脚本嵌入和固定夹具验证的是接口与边界，不衡量真实模型、嵌入或神经 Reranker 的效果；真实服务和业务质量仍需配置凭据后验收。异步 deadline 不能强制终止操作系统 DNS 线程或抢占同步解析，也不能替代部署层网络和资源隔离。
