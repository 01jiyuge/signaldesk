# V0.4.2 · 历史分页与生命周期

日期：**2026-10-23**。版本：**0.4.2**。延续 [V0.4.1 的可靠性改动](./V0.4.1_UPGRADE.md)，本轮完善扩展任务历史、旧库兼容升级，以及启动和记忆操作的资源收尾。

## 1. 扩展历史分页与本地详情

新增以下只读接口，继续遵守实例 Bearer 配置和项目范围校验：

| 接口 | 行为 |
| --- | --- |
| `GET /api/projects/{project_id}/sandbox/executions/page` | 分页读取本项目 Sandbox 执行历史 |
| `GET /api/projects/{project_id}/a2a/delegations/page` | 分页读取本地登记的 A2A 委托历史，不访问远端 |
| `GET /api/projects/{project_id}/a2a/delegations/{delegation_id}` | 读取本项目的本地委托缓存，不访问远端 |

两个分页接口的 `limit` 默认 **20**，范围 **1–100**；`cursor` 可省略，首次请求不传，后续原样传回服务端返回的 `next_cursor`。游标长度最多 512 字符，并绑定当前项目和记录类型；无效或跨范围游标返回 `422`。

返回结构为：

```json
{
  "items": [],
  "next_cursor": null,
  "has_more": false
}
```

`items` 中保持原有任务公开字段。`has_more=true` 时使用 `next_cursor` 继续请求；到达末尾时游标为 `null`。客户端不从可见记录数量计算下一页，也不自行构造游标。

分页采用 keyset，按创建时间降序、ID 降序排列；任务状态更新不改变创建位置。A2A 旧记录中未知创建时间的 `NULL` 排在最后，未知时间记录之间按 ID 保持稳定顺序。需要查看新提交的任务时，刷新首屏。

既有数组接口保留：Sandbox 仍接受原有 `limit`，A2A 仍接受原有 `limit`、`offset`；A2A 数组历史也按创建时间与 ID 返回新到旧顺序。原来的 `GET /api/a2a/delegations/{delegation_id}` 继续负责查询远端实际任务，新项目范围详情接口负责本地缓存读取。

## 2. A2A 创建时间与兼容升级

A2A 委托公开记录新增 `created_at`，新登记使用服务端创建时间并返回 ISO 时间字符串。V0.4/V0.4.1 已有记录没有可信创建时间，升级后保留为 `null`，控制台显示“提交时间未知”，不会用升级时间冒充任务提交时间。

Store 初始化检查既有 `a2a_delegations` 表，仅在缺失时增加可空的 `created_at` 列，并创建项目、创建时间与 ID 的历史索引。保留原有请求绑定、委托 ID、参数哈希、Task 与状态，不通过删除重建表或重新发送委托完成升级。

SQLite 在 `BEGIN IMMEDIATE` 中串行执行检查与增量升级，新增列使用 [SQLite 官方的 `ALTER TABLE ... ADD COLUMN` 机制](https://www.sqlite.org/lang_altertable.html)。PostgreSQL 使用事务级 `pg_advisory_xact_lock` 协调这些初始化操作，锁随事务结束释放，机制见 [PostgreSQL 官方 advisory locks 文档](https://www.postgresql.org/docs/current/explicit-locking.html#ADVISORY-LOCKS)。

这是针对已知旧结构的兼容步骤。项目仍未引入 Alembic 或通用版本迁移体系；升级前应备份业务库、检查点和 Store。

## 3. 控制台历史与观察隔离

Sandbox 和 A2A 历史首屏各加载 20 条，提供“加载更多”、加载状态、失败重试和已加载条数。记录按 ID 合并去重，列表顺序沿用服务端页顺序。

先前选择不在首屏时，通过项目范围的本地详情接口找回并单独保留。找回项不改变分页游标、`has_more` 或分页已加载数；后续页包含该项时合并为一条。刷新页面或切项目后返回，仍可恢复保存的选中 ID。

列表请求与当前任务观察使用独立控制器和版本校验。加载更多或刷新失败保留已有历史、选中项和下一页游标，并继续观察活动任务。迟到的旧项目页面或详情响应不能覆盖新项目、新选择；取消或提交请求期间禁用历史选择，观察入口也校验当前选中 ID，防止迟到取消回包切回旧任务。

已完成等终态 A2A 记录直接显示本地缓存，远端不可用时仍可查看已有报告。只有已有远端 Task ID 的活动记录自动查询远端状态；`PENDING` 或缺少 Task ID 的登记不自动进行远端轮询。缓存表示最近持久化的已知结果，未确认委托仍需核对并显式重试原请求。

## 4. Sandbox 启动与项目记忆

Sandbox 启动覆盖验证、排队记录提交和生产者注册的完整过程。HTTP 或工具调用方取消时，服务仍持有已经创建的启动操作，等待它完成收尾；服务关闭先等待在途启动操作结束，再取得生产者快照并执行取消、等待与资源回收，避免已写入的执行记录失去所属任务。工具调用取消还会在取得启动结果后清理已登记的活动执行。

项目记忆补充以下边界处理：

- 明确偏好的 key 必须是有效 UTF-8，内容必须可编码为标准 JSON；无效 Unicode 通过验证错误返回 `422`。路径中的非法 UTF-8 不会被静默替换后写成另一个 key，正常中文仍可使用。
- SQLite Store 在线程中构造时，如果进入上下文前被取消，会等待构造结束并关闭已经打开的连接；退出关闭和已持有的记忆操作也保留取消收尾。
- `MEMORY_MAX_ITEMS` 降配或既有摘要超量时，运行摘要的幂等重试仍执行容量裁剪。清理只针对当前项目的精确运行摘要命名空间，保留最新记录，避免误删明确偏好或其他消费者的子命名空间。

这些改动沿用显式用户偏好与运行摘要的区分，网页和模型内容不会自动变成用户偏好。

## 5. 验证范围与限制

前端受控测试 **4/4 通过**，直接执行生产扩展控制器和实际事件处理代码，仅替换 DOM、HTTP、时钟与存储边界。覆盖页外本地恢复与游标保持、跨页去重、列表失败后持续观察、迟到响应保护、项目切换及 `PENDING` 零远端查询。

真实浏览器使用隔离 HTTP 服务和每类 **27 条合成历史记录**验收：首屏 20 条加载到 27 条，选择最旧记录后重新加载，仍能在首屏之外恢复该选择且不污染游标；远端不可用时，已完成 A2A 报告仍可从本地缓存读取。这些合成记录用于历史界面测试。

完整 Python 回归 **265 项通过**，包含真实 PostgreSQL 的 6 项和真实 Docker 的 3 项集成测试（其中一项 PostgreSQL 测试结合 Docker）。新增回归覆盖同时间戳的大批摘要保留、非法 Unicode、构造/关闭二次取消，以及 Sandbox 提交窗口的断连和容量限制。离线评测保持 **9/9 场景、55/55 项期望匹配**。

GitHub Actions 同时执行这 4 项前端行为测试，保留离线和真实集成任务；本次提交的云端结论以对应 [Actions run](https://github.com/01jiyuge/signaldesk/actions/workflows/ci.yml) 为准。

前端检查可单独运行：

```bash
node --check src/signaldesk/static/app.js
node --test tests/frontend_history.mjs
```

当前仍面向单用户、单进程；新增数据库升级锁没有扩大为多 worker 执行保证。远端已接受而 ACK 丢失时仍可能留下 `PENDING`，外部恰好一次执行依赖远端幂等支持。真实模型、嵌入、外部神经 Reranker 及 LangSmith 云端效果仍未使用真实凭据验收。
