# V0.4 · Sandbox 与 A2A 已实现

日期：2026-10-22。延续现有 FastAPI、LangGraph、Deep Agents、Skills、MCP、混合检索、Store、LangSmith 与 AG-UI。

## 1. 新增能力

| 模块 | 实际行为 | 入口 |
| --- | --- | --- |
| Sandbox | Docker 容器内 Python/JSON 执行，输出与资源限制、超时/取消清理 | 控制台扩展面板；sandbox/executions API |
| A2A 服务 | 官方 SDK 1.2.2；1.0 JSON-RPC 与0.3兼容、Card、任务创建/查询/取消 | `/.well-known/agent-card.json`、`/a2a/` |
| A2A 客户端 | 管理员 alias、独立远端 token、持久委托历史和幂等 | 控制台扩展面板；a2a/delegations API |
| 自主研究工具 | `execute_python`、`delegate_research`，绑定当前项目/run | live Deep Agent 按需调用 |
| 生命周期 | 单进程有界任务、关闭取消、重启后的残留容器回收与数据保留 | 应用 lifespan 与持久表 |

Sandbox 使用固定 Docker 镜像，没有集成 Cloudflare Sandbox SDK，也不会在宿主执行提交的 Python。
A2A 是独立 HTTP 实例之间的真实协议调用，当前限定为已有远端项目研究。

## 2. 输入、权限与证据

Sandbox 不接受镜像/卷/环境/网络参数；代码和 JSON 只经 stdin 传入。默认 10s、128MiB、0.5CPU、32进程，
stdout/stderr 分别最多64KiB。容器无网络、非root、根目录只读、capabilities全移除，临时目录受限。
输出是分析产物，不能自动成为来源事实。执行表只存代码hash与有界结果，不保存源码/输入。

A2A Card 不从 Host 头推导地址；客户端不跟随重定向，只调用白名单中完全匹配的接口，响应解析前限制2MiB。
明确区分本地delegation ID与远端Task ID。用户偏好不授予工具权限，入站A2A研究不能再次自动委托。
原始异常与token不出现在A2A状态消息或进度投影中。

## 4. 配置与交付

新能力默认关闭。Sandbox按 [SANDBOX.md](./SANDBOX.md) 准备Docker和固定镜像；A2A按 [A2A.md](./A2A.md) 配置公共地址、远端alias/token/project。
双实例复现时，分别启动本地服务与远端研究服务，使用不同端口和独立数据库，并为各实例设置准确的 A2A_PUBLIC_URL。
在远端创建项目后，按 A2A.md 配置本地 alias、远端 token 与项目映射；本地验证可让两个实例均只监听回环地址。

Compose不挂载宿主Docker socket，容器化app默认不获得执行器权限。当前Sandbox的已验证路径是原生Python服务+本机Docker。
外置Docker执行器与公开多租户部署需要单独设计隔离、身份与运维流程。

新增表为sandbox_executions、a2a_requests、a2a_delegations；首次启动初始化。仍未引入Alembic，升级前需备份业务、checkpointer和Store。
Dockerfile已补复制evals，避免打包固定评测样本时缺文件。若 AppleDouble 文件或扩展属性导致 Docker 上下文加载失败，
可使用干净的 Git checkout 或不含这些附加文件与属性的源码副本构建；不要复制运行数据和密钥文件。
