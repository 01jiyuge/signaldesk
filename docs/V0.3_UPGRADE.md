# V0.3 · 技术栈落地与验收

日期：2026-10-22。以 V0.2 为基础保留项目、来源、历史报告和运行配置语义，加入以下实际模块。

## 1. 功能与接口

| 层 | 实现 | 可查看入口 |
| --- | --- | --- |
| 服务 | Python + FastAPI，业务 REST、能力状态与错误处理 | `/docs`、`/api/capabilities` |
| 编排 | LangGraph 五阶段图、检查点、恢复、取消 | 运行详情 |
| 研究 | Deep Agents + LangChain、虚拟 Skills、受限工具 | `research.py`、`skills/` |
| 互通 | 白名单 MCP 客户端、只读 stdio MCP 服务 | `signaldesk-mcp` |
| 检索 | PostgreSQL 全文/GIN、pgvector、RRF 与 Reranker；SQLite FTS5 | 项目证据搜索 |
| 记忆 | Checkpointer 管进度，Store 管偏好与运行摘要 | 控制台项目记忆、memory API |
| 交互 | AG-UI 标准事件经 SSE 订阅业务任务 | `/api/runs/{id}/ag-ui` |
| 评测 | 离线固定场景、可选 LangSmith 实验上传 | `signaldesk-eval` |
| 后续 | Sandbox + A2A | 见路线图，当前没有执行入口 |

AG-UI 是标准事件投影，不提供通用 RunAgentInput 运行端点；现有 REST 负责创建、恢复与取消任务。
默认 Reranker 是 lexical 确定性基线，HTTP 模型重排接口可配置，但本轮没有调用真实神经重排服务。

## 2. 一致性与记忆规则

来源检索遵守项目、已完成运行与每个 URL 最新版本边界。向量允许相同正文复用，不允许用旧正文替代新正文。
明确偏好只由用户写入；模型生成的运行摘要单独存放，标记引用结构校验通过而非事实已证明。
collect 冻结上下文，恢复沿用原上下文；偏好变化强制重新研究，摘要的自然更新不制造重复研究。
同时间戳快照按 created_at、ID 统一排序，避免混合召回复活旧正文；AG-UI 等待任务完成最终写入再终止，保留慢 Store 的警告与完成事件。记忆与原始配置不投影到公开进度事件。共享 token 仍是单用户保护，不是团队鉴权。

## 3. 验证结果

- 完整测试 **114 passed**，包含实际 PostgreSQL 集成测试 3 项。
- 原生 PostgreSQL 18.4 + pgvector 0.8.7 在独立本地测试库通过全文、向量、Store、checkpointer 和 FastAPI 生命周期验证。数据为测试夹具；没有调用嵌入服务。
- 离线质量 **9/9 场景、55/55 项期望**，覆盖 baseline/changed/unchanged、规则变化、采集失败可见性和错误引用拒绝。
- Chrome 网络与界面验证通过：真实 SSE、断线 after 游标续传、切项目中止订阅但保留任务、记忆增改删、项目隔离与重启后保留。
- Ruff、JS、依赖锁、Compose 配置检查通过；wheel 打包含 3 个 Skills、静态页面和评测样本。

测试只能证明相应边界。没有执行真实模型/嵌入/模型 Reranker/外部 MCP、LangSmith 云端上传或容器镜像构建；真实情报效果待配置后人工验收。

## 4. 运行与升级

新建环境按 README 启动；已有 SQLite 用户备份业务、检查点与记忆文件后升级。新增 FTS5 表/触发器由启动初始化，已有快照自动回填全文索引。PostgreSQL 启动创建 GIN 索引，开启向量另需 vector 扩展权限。
业务数据结构演进尚无 Alembic，不支持把任意历史 schema 自动迁移为新版本；不要直接将未备份生产库当测试库。

新增配置见 `.env.example`：MEMORY_URL、MEMORY_MAX_ITEMS、ENABLE_FULLTEXT_SEARCH、RETRIEVAL_CANDIDATES、RERANKER_*。
PostgreSQL 三个 URL 的驱动不同：业务用 postgresql+asyncpg，检查点/Store 用 postgresql。

下一阶段先以真实来源和人工标注验证研究质量，再引入调度、生产队列、Sandbox 与 A2A。完整目录和接口见 ARCHITECTURE.md。
