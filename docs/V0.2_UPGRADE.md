## API 增量

```text
PUT /api/projects/{project_id}
  Body: 与 ProjectCreate 相同的完整配置
  200: ProjectRead；404: 项目不存在；409: 活动任务冲突；422: 参数不合法

GET /api/runs/{run_id}/export?format=markdown
GET /api/runs/{run_id}/export?format=json
  200: 附件；404: 运行不存在；409: 未完成或报告不完整；422: 格式不支持
```

上述接口使用现有 Bearer 认证。导出使用净化后的运行 ID 文件名；Markdown 对外部文本转义 HTML 和 Markdown，主动链接仅允许安全 HTTP(S) URL。

## 数据兼容与恢复

本轮没有新增业务表或改变已有物理列。新字段 `report.stats` 位于报告 JSON，旧报告缺少该字段时按现有证据推导展示。配置快照复用事件表。

`configuration` 事件内保存 `data.project`，包含项目 ID、名称、说明、来源、关注重点和创建时间。修改项目不会改变已有任务配置。旧任务缺少快照且配置已变时记录 `configuration_invalidated`，恢复接口返回 409。快照缺失但项目尚未编辑的旧任务仍按兼容路径读取当前配置。

顶层图仍采用节点级检查点。research 内部没有独立检查点，恢复可能重跑模型调用；引用校验失败时直接恢复会重复校验同一份草稿，应核查后新建任务。

## 无变化判定的边界

- 比较的是提取后的正文指纹，不代表产品所有渠道都没有变化。
- 只有成功读取的来源参与内容比较，缺失来源单独显示无法判断，不宣称全覆盖。
- live 模式还比较历史运行的来源集合、项目说明、关注重点；配置变更或历史配置不明时仍调用研究。
- 未变化快照不重新生成文档嵌入。显式启用的其他外部服务是否收费，取决于其配置与调用。
- 模型访问配置仍需有效；无变化优化不会将 live 静默切换为 demo。

## 验证

本轮完整自动测试：**60 passed**。Ruff 检查、格式检查、Node JavaScript 语法检查、依赖锁检查通过。

新增覆盖包括：

- 来源编辑、活动任务冲突、跨 Repository 并发与历史保留。
- 不可变运行配置、旧任务恢复禁用和立即 start/cancel 的事务回收。
- 导出认证、报告完整性、Markdown 转义、安全 URL 和附件文件名。
- demo 新旧事实与原文引用、部分来源失败、同正文但关注规则改变仍研究。
- 无变化不调用研究、不生成文档嵌入；不完整检查点不能标为完成。
- 错误信息脱敏、安全处理建议与完成状态保护。

浏览器已实测：编辑原演示项目的名称/说明/来源名称并保留旧两次历史；第三次 v2 正确显示无变化；Markdown 与 JSON 实际下载并读取校验；新演示项目 v1→v2 显示可读变化且报告正文不含原始 diff；390×844 视口无横向溢出；断网时禁用不可用操作并在恢复网络后自动重连。页面自身错误日志为空。

V0.2 验收时未使用真实模型/嵌入密钥，PostgreSQL、pgvector、云端 LangSmith 与外部 MCP 尚未完成真实服务验收；后续验证状态见 [ROADMAP.md](./ROADMAP.md)。当时的公网采集冒烟遇到代理 fake-IP DNS 限制，未为测试绕过地址检查。
