# V0.4.5 · 轻量历史与记忆范围

日期：**2026-10-23**。版本：**0.4.5**。延续 [V0.4.4 的状态、索引与协议收尾](./V0.4.4_UPGRADE.md)，本轮减少研究历史列表读取完整报告的开销，完善页外选择和活动任务观察，并统一项目记忆的精确范围与完整扫描判断。最终验收结果见第 5 节。

## 1. 项目运行历史轻量分页

新增 `GET /api/projects/{project_id}/runs/page`，沿用 Bearer 与项目范围校验。参数为 `limit` 和可选 `cursor`：默认每页 **20** 条，`limit` 范围 **1–100**，游标最长 **512** 字符。项目不存在返回 `404`；非法、跨项目或跨记录类型的游标返回 `422`。

响应结构为：

```json
{
  "items": [],
  "next_cursor": null,
  "has_more": false,
  "active_run": null
}
```

`items` 中每项为 `RunSummaryRead`，仅有以下字段：

```text
id, project_id, mode, demo_revision, status, stage, error, created_at, updated_at
```

摘要**完全没有 `report` 字段**，不是把报告设为 `null`；数据库 SELECT 也只读取上述列。没有加载报告不等于该运行没有报告，控制台需在选择后通过已有 `GET /api/runs/{run_id}` 获取详情。当前不返回总数，也不扫描报告 JSON 来抽取标题或正文摘要。

分页沿用 `history.py` 的 keyset helper，按不可变的 `created_at DESC, id DESC` 排列；游标绑定当前项目与 `runs` 记录类型。相同创建时间由 ID 确定顺序，新插入的较新运行通过刷新首屏出现，不混入已经开始的旧历史遍历。`updated_at` 继续用于合并同一运行的新状态，不用于移动分页位置。

`active_run` 每页都返回，值为当前项目唯一 queued/running 运行的轻量摘要或显式 `null`。它独立查询整个项目，不受当前页或游标影响，因此恢复一个很旧的运行后，即使它不在首屏，仍能保持编辑和启动限制。客户端状态只用于交互提示，服务端活动唯一约束与 `409` 继续兜底并发冲突。

## 2. 旧接口、索引与启动恢复

旧 `GET /api/runs?project_id=...` 及 `Repository.list_runs()` 保持兼容，仍全量返回含 `report` 的 `RunRead`。新控制台与新历史调用方应使用分页接口；单条详情、取消/恢复、导出与 AG-UI 路由保持原有契约。

`runs` 增加索引 `ix_runs_project_created_id`，字段顺序为 `(project_id, created_at DESC, id DESC)`。初始化除了创建新库结构，还对已有表显式执行缺失索引检查和补建；不会删除重建运行表，也不修改任务、报告或时间戳。

启动恢复改用 `Repository.list_active_runs()` 的轻量摘要，仅查 queued/running 记录，不再为判断哪些任务需要标记 interrupted 而载入全部历史报告。已有的显式手动恢复策略保持不变。

本轮没有数据库字段迁移或新增依赖。已有库会新增上述索引；按既有流程备份业务库、检查点与 Store 后更新并重启即可，索引补建完成后按正常启动流程服务请求。

## 3. 控制台分页与页外记录

研究历史首屏 20 条，提供“加载更多”。已加载条数只计算真正来自分页 `items` 的去重记录；下一页使用服务端返回的 `next_cursor`，不从可见记录数量推算。

保存的选中 ID 不在首屏时，单独获取详情并作为页外选中项保留；`active_run` 也可作为页外活动项展示和观察。两类保留项都不改变分页顺序、游标、`has_more` 或已加载条数，后续页包含相同 ID 时合并去重。

完整详情按选择读取，后台活动摘要更新不触发额外的完整报告 GET。活动任务订阅继续遵守既有 AG-UI 契约；JSON 兼容轮询可用同一分页接口的 `limit=1` 刷新 `active_run`，忽略该次响应的分页位置，不重置已加载历史。

临时网络或服务错误应保留当前选择、已加载历史及其重试入口；明确返回 `404` 时才清理无效选中项。首屏加载失败不能解释成“没有活动任务”，旧页或旧详情的迟到响应也不能覆盖切换项目、恢复或新选择后的状态。这些时序已由生产脚本的受控 HTTP/SSE 回归覆盖，关键分页与恢复路径也通过独立浏览器验收。

## 4. 项目记忆的精确范围与有界完整扫描

LangGraph Store 的 `asearch()` 按命名空间前缀搜索。项目记忆不能把后代命名空间或其他消费者的记录直接当作当前项目偏好和摘要，也不能因为前面若干条不属于自己，就认为自己的记录已经全部读完。

本轮统一精确扫描逻辑，保留现有服务端固定命名空间：

| 类别 | 精确命名空间 | 记录标记 |
| --- | --- | --- |
| 用户明确偏好 | `("projects", project_id, "preferences")` | `kind="preference"`、`source="user"` |
| 运行摘要 | `("projects", project_id, "runs")` | `kind="run_summary"`、`source="verified_run"` |

每次扫描都从 `offset=0` 读取并逐步扩大窗口，`base=MEMORY_MAX_ITEMS+64`，最多 **4 次**请求，窗口上限为 `8*base+1`。只有返回条数小于本次窗口的短页，才能证明匹配前缀范围已经读完；最大窗口仍满页时，不能假设余下没有记录。该方式避免依赖 PostgreSQL Store 在同时间戳下未约束的 OFFSET 页顺序。

确认有界完整集合后，再筛选精确命名空间及类别，并按 `updated_at DESC, key DESC` 排序。明确偏好、运行摘要各自应用 `MEMORY_MAX_ITEMS` 配额；后代命名空间和其他类别不占用本类别配额，也不能成为返回的项目上下文。等时间戳时应用 key 排序，避免只按到达顺序任意保留或展示。

同一精确命名空间里，被其他类别占用的 Store key 受到保护：不作为应用自己的偏好或摘要读取，也不覆盖、删除。运行摘要裁剪只处理自己拥有的摘要，不删除明确偏好或其他消费者的数据；网页和模型文本依旧不能自动成为用户偏好。

重复条目、无进展或在最大窗口内无法证明完整读取时，抛出受控的 `MemoryLimitError`。项目记忆 GET 列表也返回 `409`，不把不完整结果当成空记忆、有效配额计数或可安全裁剪的集合。需要检查外来记录和历史溢出后重试，不通过删除不属于应用的数据来强行腾出容量。

## 5. 升级与验收边界

完整 Python 回归 **457 项通过**，包含真实 PostgreSQL **11 项**与真实 Docker **3 项**（一项 PostgreSQL 测试同时使用 Docker）；前端 **32/32**，Ruff/格式、JS 语法、锁文件检查通过；离线评测 **9/9 场景、55/55 项期望匹配**。覆盖：

- 分页 SQL 不读取报告列、默认与最大页大小、空历史、同时间戳顺序、翻页间插入和游标范围隔离。
- 页外活动任务在每页可见并阻止编辑/重复启动，旧接口与单条详情兼容。
- 旧库缺失索引自动补建且数据保留，启动恢复不调用全量历史读取。
- 首屏与加载更多、页外选择恢复、按需详情、临时失败保留和 `404` 清理，以及切项目和迟到响应。
- 精确命名空间、类别配额、相同时间排序、外来 Store key 保护，及无法证明完整扫描时的受控 `409`。

上一版 [V0.4.4 验证历史](./V0.4.4_UPGRADE.md)保留原结论，不作为本轮已经完成验收的依据。具体启动与显式真实依赖测试开关见 [OPERATIONS.md](./OPERATIONS.md)，每次发布的远端检查见 [GitHub Actions](https://github.com/01jiyuge/signaldesk/actions/workflows/ci.yml)。

当前仍面向本地单用户、单进程。分页、索引和有界 Store 扫描不增加多 worker、跨进程任务所有权或多租户权限保证。真实模型、嵌入、外部神经 Reranker 和 LangSmith 云端效果仍需配置凭据并独立验收；固定夹具和受控协议测试不衡量真实业务质量。

浏览器使用独立合成项目：27 条记录、每份报告约 100 KB。验证首屏 20 条，较早的活动任务在页外仍锁定编辑与启动，加载更多后共 27 条；查看第 2 次旧报告并重载，首屏保持 20 条且旧选择恢复；后台任务完成后无需重新加载页面即可解除写操作限制。独立观察的失败与 JSON 回退时序另由受控测试覆盖。

同一夹具在较早任务仍执行、其余 26 条含报告时，旧全量历史接口返回 **2,626,882 字节**，分页首屏摘要返回 **5,848 字节**（20 条摘要与独立活动摘要）。这仅比较两个历史列表响应，不包含随后选中报告、其他接口与 SSE，不据此声称整体页面加速比例。新分页 SQL 不选择 `report` 列；真实 PostgreSQL 验证分页排序、插入间隙与页外活动约束。
