# V0.4.3 · 采集、检索与交互边界

日期：**2026-10-23**。版本：**0.4.3**。延续 [V0.4.2 的历史分页与生命周期改动](./V0.4.2_UPGRADE.md)，本轮完善真实页面采集、检索与外部重排的资源边界，以及 API 输入和控制台异步交互。本轮完整验收结果见第 6 节。

## 1. 页面采集：原始字节与整体网络超时

采集请求显式发送 `Accept-Encoding: identity`，通过 HTTPX 流式读取原始响应字节。声明的 `Content-Length` 超限或格式无效时提前拒绝；实际读取仍独立累计，不能通过省略或缩小声明长度绕过 `MAX_SOURCE_BYTES`。超过上限后退出响应上下文并关闭流，不再先完整读取、自动解压后才检查大小。

当前只支持未压缩响应。服务端强制返回 `gzip`、`br` 等非 `identity` 内容编码时，采集明确失败，不自动解压或降级重试。依赖强制压缩的来源需要提供可返回未压缩内容的公开入口；这项兼容性变化同样适用于本轮 HTTP Reranker。

`REQUEST_TIMEOUT_SECONDS` 现在也作为一次页面采集的整体异步网络时间预算，覆盖 URL 校验中的 DNS 等待、所有手动重定向，以及正文读取。持续发送少量数据和多次重定向都不会重新获得完整预算。HTTPX 自身的连接、读写与连接池超时仍保留；其中读超时按等待数据块计算，因此还需要外层整体预算，机制见 [HTTPX 超时文档](https://www.python-httpx.org/advanced/timeouts/)。

每次请求显式禁用客户端自动重定向，即使注入的客户端默认开启自动跳转，也由采集器逐跳校验目标。现有 HTTP(S)、公网地址、凭据和端口限制继续生效；DNS 重绑定仍需部署层出口策略配合。

HTML 原始字节交给解析器，使 BOM 和页面 `meta charset` 能参与解码；HTTP 声明字符集时先确认它是可用的文本编码。纯文本按有效 HTTP 字符集解码，未声明时使用 UTF-8 并处理 UTF-8 BOM。媒体类型按大小写不敏感方式匹配，未知字符集或非文本 codec 返回稳定的公开错误。

| 采集错误码 | 含义 |
| --- | --- |
| `source_too_large` | 声明长度或实际原始正文超过单页上限 |
| `source_unsupported_content_encoding` | 来源返回了非 `identity` 内容编码 |
| `source_invalid_content_length` | 来源声明长度格式无效 |
| `source_invalid_charset` | HTTP 文本字符集无效或不可用 |
| `source_timeout` | 整体采集预算或 HTTPX 网络操作超时 |

读取使用 [HTTPX 的 `aiter_raw()`](https://www.python-httpx.org/async/#streaming-responses)，避免先应用内容解码。已由调用方提前完整加载的测试响应只能检查现有字节；生产网络路径保持 `client.stream()`，才能在读取期间执行限额。外部任务取消继续向上传播，并退出响应上下文清理连接。

## 2. 检索：最新来源版本与嵌入错误

可移植词法基线先在当前项目的 `completed` 任务中，为每个 URL 选取最新快照，再对这些去重后的来源应用最多 **1000 条**的候选扫描上限。一个 URL 的大量历史版本不再先占满候选窗口，挤掉其他来源。这里的上限是词法基线扫描上限，不是历史记录删除或全文、向量检索的统一存储容量。

最新版本按快照创建时间降序、快照 ID 降序确定；词法评分相同时使用同样的时间与 ID 顺序。全文、向量结果及融合、重排也补充稳定的并列顺序，减少相同输入因数据库返回顺序不同而变化。检索仍限制在当前项目的已完成证据中，不把失败任务或其他项目的快照作为历史知识。

向量路径校验嵌入结果数量、`EMBEDDING_DIMENSIONS` 维度和每项数值：拒绝布尔值、非数值、`NaN`、无穷值及维度错误。查询嵌入和批量索引调用受异步时间预算约束；服务调用失败或返回无效结果时，转换成安全、可重试的应用错误。

公开错误码分别为 `embedding_query_failed` 与 `embedding_index_failed`。经 HTTP API 返回时状态为 `503`，包含操作建议，不向客户端回传原始服务异常、凭据或响应正文。向量功能没有启用时，继续使用已有词法与全文能力；开启后的嵌入故障会明确暴露，便于排查配置和服务状态。

## 3. HTTP Reranker：流式限长与结果校验

HTTP Reranker 同样使用 `client.stream()`、`Accept-Encoding: identity` 和原始字节限长，在有界读取完成后解析 JSON。强制压缩、无效长度或超限响应都作为重排失败处理。每次调用也显式禁用自动重定向，防止注入客户端的默认配置将证据或鉴权信息转发到跳转目标。默认词法 Reranker 不访问该 HTTP 服务。

新增配置：

| 环境变量 | 默认值 | 范围与行为 |
| --- | --- | --- |
| `RERANKER_MAX_RESPONSE_BYTES` | `1048576`，即 1 MiB | `1024`–`5242880` 字节，限制 HTTP 重排原始响应正文 |
| `RERANKER_TIMEOUT_SECONDS` | `20` 秒 | 现有配置，`1`–`120` 秒；同时约束整个异步 HTTP 调用和正文读取 |

返回结果继续检查条数、索引范围、重复索引与有限分数，并为并列分数提供稳定顺序。服务失败或结果无效时返回可重试的 `reranker_failed`，不会把不完整响应当成成功排序。

上述整体预算采用 [`asyncio.timeout()`](https://docs.python.org/3.11/library/asyncio-task.html#asyncio.timeout)，通过取消当前异步任务结束等待；调用方主动取消继续保留取消语义。

## 4. API：有效 Unicode、有限 JSON 与验证回包

`/api` 下的 JSON `POST`、`PUT`、`PATCH` 在已有原始请求体字节限制内，进一步检查内容可跨越 JSON、UTF-8 和数据库边界。无法解码的 JSON 字节、字符串或对象 key 中未配对的 Unicode surrogate、`NaN`、正负无穷，以及解析后溢出为无穷值的数值，返回 `422` 和 `invalid_json_body`。合法中文、emoji 和有限数值继续支持。

应用验证失败的 `detail` 保留字段位置、错误类型和说明，移除原始 `input` 等输入回显字段，避免把提交内容或无法安全序列化的对象放进错误响应。调用方应根据字段位置修正请求，不依赖错误回包取得原始表单数据。

已有 `MAX_REQUEST_BYTES`、超限 `413` 和非 `identity` 请求内容编码 `415` 继续适用于 `/api` 与 `/a2a` 写请求。A2A 同样预检 JSON 安全边界，但使用 JSON-RPC 错误封装：非法 Unicode 或非有限数值返回 HTTP `200`、`error.code=-32600`；非法 JSON 语法返回 HTTP `200`、`error.code=-32700`，两者的 `id` 均为 `null`。有效请求继续交给官方 SDK，A2A 不套用业务 API 的 `422` 封装。GET、HEAD 和 SSE 继续保持读取或流式行为，不为这项 JSON 检查预缓冲。

## 5. 控制台：鉴权与迟到响应保护

公开 `/api/health` 成功只代表服务健康。控制台必须成功读取受保护的项目列表，才解除写操作限制。连接验证中或 Token 错误时展示明确状态，并禁用研究启动、编辑、取消/恢复、项目和记忆保存，以及 Sandbox/A2A 提交与取消；已经提交的后台任务继续运行。

连接拥有独立版本标记。重连或修改连接时中止旧连接探测、搜索和记忆请求；迟到的旧响应不能把新连接标成已就绪，也不能回填上一连接的数据。验证成功后重新加载项目并订阅研究状态。

项目表单另有草稿版本校验，覆盖重新打开、Escape 关闭、继续改稿和连接变化。同一连接下的旧提交成功可以更新项目列表，但不会关闭新打开的表单、覆盖新草稿或强制切换当前项目。记忆保存成功也不会清空提交后继续修改的草稿。

证据搜索保留当前查询与请求版本。JSON 兼容轮询观察到研究完成时，仅在没有搜索关键词的情况下刷新默认证据，避免完成回包覆盖用户正在查看的搜索结果。

## 6. 升级与验收

本轮无需清空历史数据。已有部署升级前仍应备份业务库、检查点和 Store，随后更新依赖并重启；项目尚未引入通用版本迁移体系。`RERANKER_MAX_RESPONSE_BYTES` 可不配置，默认使用 1 MiB；需要重排服务支持未压缩响应。

本轮验收：**344 项 Python 测试全部通过**，包含真实 PostgreSQL 的 7 项与真实 Docker 的 3 项集成测试（其中一项 PostgreSQL 测试同时使用 Docker）；**12 项前端行为测试全部通过**。Ruff 检查与格式、JavaScript 语法、锁文件检查通过；离线评测为 **9/9 场景、55/55 项期望匹配**。覆盖：

- 采集的压缩响应拒绝、原始字节上限、慢流与跨重定向整体超时、字符集、取消和连接关闭。
- 大量同 URL 历史下的来源覆盖、同时间戳稳定顺序，以及嵌入服务错误和非法向量。
- HTTP 重排超限、压缩、慢流、整体超时和无效排序结果。
- API 的非法 Unicode、非有限 JSON 数值和验证回包输入隔离，以及 A2A 的安全 JSON-RPC 错误封装。
- 错误 Token、乱序连接响应、新旧表单和记忆草稿，以及研究完成与搜索并发。

浏览器在独立、合成数据的 HTTP 服务上实际验证：无 Token 或错误 Token 显示访问失败并禁用提交；正确 Token 恢复项目；完成演示研究和 AG-UI 事件同步；再次鉴权失败时保留已有报告但禁用操作；重新验证后恢复访问。乱序连接、迟到提交和 JSON 轮询覆盖搜索等时序由前端受控测试验证。

运行方式沿用 [操作文档](./OPERATIONS.md)，历史验证结果保留在 [V0.4.2 说明](./V0.4.2_UPGRADE.md)。远端检查的实际状态见 [GitHub Actions](https://github.com/01jiyuge/signaldesk/actions/workflows/ci.yml)。

当前仍面向本地单用户、单进程；本轮资源限额和请求版本保护没有扩大为多 worker 或分布式执行保证。异步 deadline 无法强制终止已提交到线程中的操作系统 DNS 查询，也不能抢占同步 HTML 解析；原始字节限额降低了处理规模，但不构成 CPU 隔离。需要更强网络或 CPU 边界的部署仍应采用出口策略和独立工作进程等措施。

真实模型、嵌入、外部神经 Reranker 及 LangSmith 云端效果仍未使用真实凭据验收。受控 HTTP 或离线夹具验证的是接口、资源边界与错误行为，不衡量这些服务的实际质量。
