# V0.4.6 · 分批事件回放

日期：**2026-10-23**。版本：**0.4.6**。延续 [V0.4.5 的轻量历史与记忆范围](./V0.4.5_UPGRADE.md)，本轮处理长任务事件积累后的重连开销：数据库分批读取、终态前排空日志，以及控制台仅保留最近事件的显示窗口。

## 1. 有界事件页

新增 `GET /api/runs/{run_id}/events/page?after=0&limit=100`。沿用 Bearer 认证，运行不存在返回 `404`，非法参数返回 `422`。`after` 为非负数据库事件 ID，最大 `2147483647`；`limit` 默认 **100**，范围 **1–200**。

```json
{
  "items": [],
  "next_after": 0,
  "has_more": false,
  "producer_active": false
}
```

每页仅查询当前运行且 `id > after` 的事件，按 ID 升序排列，数据库最多读取 `limit + 1` 条判断后续页。`next_after` 是本页最后返回的事件 ID，空页保持输入 `after`。全局事件 ID 可以有空隙，客户端不能按条数推算下一游标。翻页期间新追加的事件可在后续请求读取。

`producer_active` 表示本地研究任务或恢复/取消状态写入是否仍在进行，服务在读取这一页**之前**采样。客户端只有同时看到 `has_more=false`、`producer_active=false`，且任务处于终态时，才能停止 JSON 轮询。先采样后查询可保证生产任务退出前提交的最终日志仍由这一页或后续页读取，不把一次暂时的空尾页当作永久结束。

新接口使用与 AG-UI 相同的公开事件投影：不返回原始配置、记忆上下文、请求头或异常诊断。旧 `GET /api/runs/{id}/events` 继续保留原数组契约与完整内部事件数据，供已有受信任调用方兼容；新控制台使用分页接口。

`events` 增加 `(run_id, id)` 复合索引，初始化为旧表显式补建缺失索引。不修改已有事件、任务、报告或检查点。本轮没有新增依赖或数据列。

## 2. SSE 分批排空与续传

AG-UI 使用事件页按批回放。分页仍有积压时继续读取，并让出事件循环、检查断开；不会因为数据库中的任务状态已完成，就在积压日志尚未发送时提前结束流。

终态投影继续等待本地生产任务完成 Store 和最终日志写入，再确认未接收事件已排空。只有 `CUSTOM(name="signaldesk.event")` 携带持久化 SSE ID；状态和阶段投影不推进数据库游标。断线后从最后确认的事件 ID 续传，断开观察不会取消研究。

这是每次数据库查询的条数限制，不是整个订阅总事件数或每条记录字节数的限制；大报告仍遵循既有快照省略与 REST 详情获取规则。

## 3. 控制台事件窗口与 JSON 回退

控制台仅显示最近 **200** 条执行事件，达到窗口限制后给出说明。较早事件继续保留在服务端，可用事件页接口按游标读取；显示窗口不回退已确认游标，也不删除数据库记录。

SSE 与 JSON 回退共用事件合并逻辑，重复事件不重复显示。JSON 回退按页读取，并限制单轮页数；即使所选运行已经完成，只要仍有未读页或本地生产任务尚未退出，就继续排空。等待最终写入时使用正常轮询间隔，不用固定等待次数推断完成。请求失败保留已接收事件与游标，重试从已确认的位置继续。旧项目、旧选择和恢复前请求的迟到响应不能推进当前选择的游标。

`RUN_ERROR` 的 `stream_unavailable` 代码表示订阅暂时不可用，选中任务和背景任务都会保留确认游标并重连；业务失败的终态仍按原规则处理。

窗口裁剪后同步更新 DOM，不因数量保持 200 而漏掉后续事件；列表自动滚动仍尊重用户正在查看的位置。

## 4. 升级步骤与验证范围

1. 停止单进程服务，备份业务库、checkpointer 和 Store。
2. 更新代码并执行 `uv sync --frozen --extra dev`。
3. 启动服务，初始化补建事件复合索引，现有事件与报告继续保留。
4. 检查长历史的分页、断线续传与最后完成事件；旧 API 调用方可继续使用原接口，新调用方优先使用事件页。

测试重点包括：多批事件的顺序、跨运行隔离、追加期间的游标、空页与输入边界、公开投影、旧库索引保留数据、终态前完整排空、生产任务迟到日志、断线重连，以及控制台窗口裁剪和失败重试。

完整 Python 回归 **485 项通过**，包含真实 PostgreSQL **12 项**与真实 Docker **3 项**（一项 PostgreSQL 同时使用 Docker）；前端 **42/42**，Ruff/格式、JS 语法、锁文件检查通过；离线评测 **9/9 场景、55/55 项期望匹配**。

隔离 HTTP 与浏览器夹具各有 651 条合成事件。事件页共 7 页、每页最多 100 条；SSE 完整发出 651 个 CUSTOM 后发送终态，JSON 兼容回退完整续读后停止。浏览器显示最近 200 条（合成事件 451–650），并成功从 JSON 回退重新连接 AG-UI。临时服务和测试数据与用户工作区分离。验证命令与真实 PostgreSQL/Docker 开关见 [OPERATIONS.md](./OPERATIONS.md)，当前状态见 [ROADMAP.md](./ROADMAP.md)。本轮不改变本地单用户、单进程的执行范围，也不代表真实模型、嵌入或远端 Reranker 效果已经验收。
